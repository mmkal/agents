# Macwright Demo Automation

## Status

Complete for the branch scope. The first natural-language recipe spike has been retired; the maintained demo surface is now `Macwright.create(...)` with explicit Vitest steps, native macOS automation, OCR/DOM locators, and video tooling. Remaining work is normal hardening of the UI demos on an interactive desktop session.

## Assumptions

- This branch may add a root `package.json`, TypeScript config, and test setup to this repo.
- Demo specs should be plain Vitest files that call `Macwright.create(expect.getState().currentTestName)`.
- UI-heavy examples are opt-in and should not run as part of normal `pnpm test`.
- The maintained path should use the Swift-backed Macwright daemon instead of baking shell recipes into test source.
- It is acceptable for examples to depend on an unlocked macOS desktop with Accessibility and Screen Recording permissions.

## Original Direction

The original ask was to create a Vitest-driven way to demo tools on the local computer, starting with a small example and growing toward a Cursor/TypeScript screen recording. The first idea was a natural-language step runner that rewrote its own test source with concrete execution details. Git history shows that became useful only as a tracer bullet: soon after, the work pivoted to an explicit Playwright-like API for the whole computer, first prototyped in the Cursor TypeScript demo, then extracted into a helper, then backed by a Swift daemon, and finally renamed to Macwright.
